# 代码变更影响评审

> **结论：通过 / 有条件通过 / 不通过 / 无法完成**
> **风险：高 / 中 / 低 / 未知**

一句话写清影响的业务、确认的问题和合入条件。

## 审核发现

没有确认问题时明确写：**未发现可证明的代码缺陷。**

### P1-01 问题标题

| 项目 | 结论 |
|---|---|
| 代码位置 | 文件、行号、符号 |
| 触发条件 | 能触发问题的输入、状态或调用路径 |
| 问题机制 | 错误行为如何发生 |
| 实际影响 | 用户、业务或系统可观察到的结果 |
| 修改要求 | 开发需要完成的修改 |
| 完成标准 | 可判断的验证条件 |

## 语言规范与基础审核

Reviewer：实际执行评审的 Agent
Review 结果：通过 / 有条件通过 / 不通过 / 无法完成

只保留本次改动涉及的语言，并从对应语言知识包复制完整检查项。每项填写 `通过`、`不通过`、`不适用` 或 `未验证`，同时给出源码或验证依据。

| 序号 | 审查项 | 结果 | 依据 |
|---|---|---|---|
| 1 | 对应语言的编码规范和基础检查项 | 通过 / 不通过 / 不适用 / 未验证 | 文件、行号、测试或限制 |

## 业务影响与测试范围

本节只使用业务语言，不出现文件名、函数名、变量名或调用链。

| 业务场景 | 影响 | 测试级别 | 可观察的预期结果 |
|---|---|---|---|
| 具体操作场景 | 行为变化或风险 | 必测 / 建议回归 / 无需专项回归 | 可直接判断的结果 |

## 结论依据

- 变更范围：基线、目标版本、仓库和变更规模。
- 已确认路径：用简短文字说明已由图谱定位并经源码核验的路径。
- 图谱状态：已初始化、已更新或存在的限制。
- 已执行验证：静态检查、测试或未执行项。

## 限制与剩余风险

- 列出未覆盖仓库、动态调用、运行配置、生成代码、构建条件和未执行测试。
- 没有限制时明确写“无已知限制”。
