# Lua 编码规范与基础审核

## 编码规范

- 遵循仓库现有缩进、命名、模块和错误处理风格；新增变量默认使用 `local`，避免隐式全局变量。
- table、userdata、字符串和数值使用前检查 nil、类型、边界和默认值；跨接口转换不得静默改变类型或精度。
- `ipairs` 会在第一个 nil 处停止，只能用于从 1 开始且连续的数组。稀疏数组、混合键或非连续数字下标使用 `pairs`、显式索引集合或明确边界的数值循环。
- 不直接修改共享或全局配置表。确需派生修改时深拷贝，并明确生命周期、恢复策略和并发影响。
- 缓存 key 必须包含完整业务维度；定义初始化、覆盖、失效、清理和异常恢复行为。
- 保持新老客户端、券商差异和协议字段兼容；局部生效的变更必须有可验证开关及默认行为。
- 外部调用、配置、数据库和异步返回必须处理空值、超时、错误类型和异常状态，并提供必要日志、告警和降级；日志不得泄露敏感数据。
- 循环、序列化、后台交互和大 table 操作要评估复杂度、并发与内存开销。
