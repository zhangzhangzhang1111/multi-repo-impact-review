# C 编码规范与基础审核

## 编码规范

- 遵循仓库现有格式、命名、头文件和返回码约定；函数接口说明缓冲区长度、所有权、可空性和生命周期。
- 所有变量初始化；检查指针、数组边界、长度运算、整数溢出、符号转换、结构体布局和数据截断。
- `sprintf`、`strcpy`、`strcat`、`memcpy` 等操作必须证明容量、终止符、重叠条件和实际长度安全，优先使用项目已有的有界封装。
- 每条成功和失败路径都正确释放内存、文件、socket、锁和句柄；避免重复释放、use-after-free 和泄漏。
- 外部接口处理空返回、超时、错误码、协议长度和类型错误；共享状态明确同步与回调生命周期。
- 保持 API/ABI、结构体、协议、配置和新老客户端兼容；券商定向逻辑使用明确开关、默认值和回退路径。
- 异常日志、告警和降级足以定位问题，但不记录敏感数据。
- 评估循环、内存复制、锁、后台交互、配置和数据库访问的延迟及并发上限。

## C code review checklist

| 3 | 是否存在泄漏、重复释放、越界、空指针、未初始化、整数溢出或数据截断；内存/字符串函数是否有容量证明 | 通过 / 不通过 / 不适用 / 未验证 | |
